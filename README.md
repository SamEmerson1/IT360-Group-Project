## Overview

This project is a command-line digital forensics tool that analyzes suspicious email files (`.eml` and `.msg`) and produces a structured investigative report. The goal is to take the manual work an analyst does when triaging a reported phishing message — tracing where it actually came from, checking whether the sender is who they claim to be, and pulling out anything worth blocking — and automate it into a single repeatable process.

Phishing remains one of the most common initial access vectors in real incidents, and the artifacts that prove it are all sitting in the message headers and body. This tool extracts those artifacts, evaluates them, and hands the analyst an evidence-backed summary instead of a raw email file.

## Planned Features

- **Header chain reconstruction** — parses the `Received:` headers to rebuild the message's delivery path and identify the originating server
- **Authentication analysis** — reports SPF, DKIM, and DMARC results and flags failures or missing records
- **Sender spoofing detection** — compares display name against the actual sending address and checks for lookalike or recently-registered domains
- **URL extraction and defanging** — pulls all links, unwraps redirect and tracking wrappers, and outputs them in a safe, non-clickable format
- **Attachment analysis** — identifies file types and generates MD5 and SHA-256 hashes for each attachment
- **IOC export** — writes indicators of compromise to JSON and CSV for handoff to a SIEM or blocklist
- **AI-assisted summary** — an integrated language model reviews the extracted artifacts and produces a plain-language explanation of the social engineering techniques used in the message
- **Forensic integrity** — evidence files are opened read-only, hashed before and after analysis, and every action is written to a timestamped audit log

## AI Usage Disclosure

This README was created with the assistance of an AI language model. AI tools are also used within the analyzer itself, as described in the Features section above, to generate human-readable summaries of extracted artifacts.

AI-generated output in this project is treated as **advisory only**. All forensic findings — headers, hashes, authentication results, and extracted indicators — are produced by deterministic parsing, not by the language model. The AI layer interprets and explains those findings; it does not create them.
